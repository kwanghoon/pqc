# PQC 전환 계획: ch2 - 난수 생성 및 RSA 키 생성

## 1. 전환 목적

이 장의 예제는 [ch2/mkrand16.c](mkrand16.c)와 [ch2/rsagenkey.c](rsagenkey.c)를 통해 다음을 수행한다.

- `RAND_seed()`와 `RAND_bytes()`로 난수를 생성한다.
- `RSA_generate_key(512, RSA_F4, ...)`로 512비트 RSA 키를 생성한다.
- 생성된 키를 PEM 파일로 저장한다.

이 구조는 현대적 관점에서 보면 양자 컴퓨터에 취약한 키 생성 방식이며, 키 교환/서명/인증서를 양자내성 방식으로 전환할 필요가 있다.

## 2. 현재 취약 암호 사용

- 난수 생성: `RAND_seed()` 기반의 엔트로피 주입 방식
- 키 생성: RSA 512비트
- 공개키/개인키 저장: PEM 형식의 RSA 키

이 구조는 다음 이유로 PQC 전환 대상이다.

- RSA는 쇼어 알고리즘에 취약하다.
- 512비트 RSA는 현대 보안 기준에 비해 매우 약하다.
- 키 생성 시 확보한 엔트로피와 키 유형이 양자 내성 기준을 만족하지 않는다.

## 3. 전환 목표

- 난수 생성: 양자내성 키 생성과 KEM/서명 구현에 적합한 안전한 랜덤 소스 확보
- 키 생성: RSA에서 ML-KEM 또는 ML-DSA 계열로 이동
- 키 저장: PEM 기반 구조를 유지하되 양자내성 키 형식 및 쿠버네티스/애플리케이션 스토리지 정책에 맞게 변경

## 4. 5단계 전환 계획

### (1) 알고리즘/매개변수 설정

현재:
- RSA 512 비트
- 기본 `RSA_F4` 공개지수
- OpenSSL 1.0.2의 구식 RSA API

대상:
- ML-KEM 기반 키 교환
- ML-DSA 또는 SLH-DSA 기반 서명
- 연산 파라미터(모드, 공개키 길이, 해시 알고리즘) 명시

권장 전환:
- 적용 대상 애플리케이션이 키 교환을 수행하는 경우: ML-KEM
- 서명이 필요한 경우: ML-DSA
- 하이브리드 운영이 필요한 경우: 기존 RSA를 유지하되 PQC 알고리즘을 병행 적용

### (2) 키 준비

현재:
- `RSA_generate_key()`로 개인키와 공개키를 생성
- `PEM_write_RSAPublicKey()`, `PEM_write_RSAPrivateKey()`로 파일 저장

전환 후:
- 양자내성 공개키와 개인키 생성
- PEM 또는 통합 형식으로 저장
- 키 식별정보와 알고리즘 ID를 함께 보관

주의점:
- 기존 키 파일 이름을 유지하더라도 키 형식과 알고리즘을 명시적으로 변경해야 한다.
- 키 로테이션과 이전 키 호환성 전략을 준비해야 한다.

### (3) 연산 초기화

현재:
- `RAND_seed()`로 시드 주입 후 `RAND_bytes()` 호출
- `RSA *` 객체 생성과 공개키/개인키 구분

전환 후:
- KEM/서명 전용 `EVP_PKEY_CTX` 초기화
- 개인키/공개키 컨텍스트 분리
- 알고리즘별 초기 파라미터 설정

설계 포인트:
- 난수 생성과 키 생성은 별도 API 및 정책으로 구분한다.
- `RT`(실시간) 동작 환경에서는 초기화 단계가 재사용 가능한 라이브러리 레이어로 관리되어야 한다.

### (4) 연산 실행

현재:
- 난수 생성
- 키 생성
- 키 파일 저장

전환 후:
- 양자내성 키 생성
- 양자내성 공개키 배포
- 필요 시 연산 시점에 키 교환 또는 서명 생성 수행

실행 단계에서 보장해야 할 것:
- 키 생성 속도와 메모리 사용량 평가
- 트래픽이 많은 서버 환경에서 키 생성 병목 체크
- 기존 애플리케이션과의 호환 경로 설계

### (5) 결과 처리

현재:
- 생성 결과를 파일로 저장하고 종료

전환 후:
- 생성된 공개키를 인증서 또는 배포 매니저에 등록
- 개인키는 보안 저장소에 보관
- 키 버전 관리 및 로테이션 로그 기록

권장 결과 처리:
- 공개키를 CA/인증서 체인과 연결
- 잘못된 키 버전 누락 여부 확인
- 전환 완료 후 회귀 테스트를 통한 키 포맷 호환성 검증

## 5. 적용 우선순위

1. 키 생성 API를 RSA에서 PQC 키 생성 API로 교체
2. 파일 저장 포맷을 양자내성 키 형식에 맞게 확인
3. 애플리케이션이 공개키를 받아들이는 경로를 점검
4. 키 로테이션 및 운영 절차를 함께 정리

## 6. 요약

이 장의 예제는 “키 생성의 가장 기본적인 단계를 구현한 예시”이므로, PQC 전환에서 가장 먼저 적용해야 하는 부분은 키 생성 알고리즘의 전환이다. RSA 512 비트 키는 양자 컴퓨터 공격에 취약하므로, 이 장의 전환은 단순한 라이브러리 변경이 아니라 보안 기저 기술 전체를 재설계하는 작업으로 이해해야 한다.
