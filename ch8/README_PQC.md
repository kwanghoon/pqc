# PQC 전환 계획: ch8 - DES 기반 클라이언트/서버 인증

## 1. 전환 목적

이 장의 예제는 [ch8/client0.c](client0.c)와 [ch8/server0.c](server0.c)를 통해 다음을 구현한다.

- 클라이언트가 타임스탬프를 DES로 암호화해 서버로 전송한다.
- 서버는 동일 키를 사용해 복호화 후 시간 차이를 확인한다.
- 인증 성공 여부를 `yes`/`no`로 응답한다.

이 구조는 DES 기반 키 공유와 책임 분리 방식이 이미 오래된 보안 모델이므로, 양자내성 전환을 통해 정책과 프로토콜을 재설계해야 한다.

## 2. 현재 취약 암호 사용

- 대칭 암호: DES
- 키 저장: 파일 기반 키 (`symmKey.sec`)
- 인증 방식: 시간 차이 기반의 작은 보안 판정
- 전송: TCP 소켓을 통한 암호문 전달

문제점:
- DES는 현대 보안 기준에서 취약하다.
- 키가 파일로 저장되며 노출 위험이 있다.
- 인증 로직은 단순 시간차 확인에 지나지 않아, 실제 보안 상태를 제대로 표현하지 못한다.

## 3. 전환 목표

- DES 기반 키 공유 구조를 KEM 기반 키 합의로 전환
- 실제 메시지 보호는 AES-256-GCM 또는 확장된 대칭 암호로 수행
- 클라이언트/서버 인증은 단순 시간차 비교가 아니라 양자내성 인증 및 무결성 검증 구조로 대체

## 4. 5단계 전환 계획

### (1) 알고리즘/매개변수 설정

현재:
- `DES_set_key()`
- `DES_ncbc_encrypt()`
- 타임스탬프를 암호화하는 단순 구조

전환 후:
- KEM으로 세션 키 교환
- DEM은 `AES-256-GCM` 또는 `AES-256-CTR`
- 인증에는 서명/검증 또는 키 기반 인증 방식 도입

권장 구조:
- 클라이언트와 서버는 각각 공개키와 개인키를 가진다.
- 키 합의 후 세션 키를 생성하고, 메시지 무결성은 인증 태그로 확인한다.

### (2) 키 준비

현재:
- `symmKey.sec` 파일을 읽어 DES 키를 사용
- 동일 키를 클라이언트/서버가 공유

전환 후:
- 키는 파일 기반이 아니라 안전한 키 저장소 또는 장치별 보관 구조 사용
- KEM 키 쌍 생성
- 공개키는 서버/클라이언트 사이에 교환되며, 세션 키는 동적으로 생성

중요 점:
- 공유 비밀키 구조는 양자 컴퓨터 공격에 취약하므로 설계 자체를 재변경해야 한다.
- 키 교환의 보안성을 지원할 수 있도록 키 로테이션 정책을 준비해야 한다.

### (3) 연산 초기화

현재:
- `DES_set_key(&rawkey, &keySched)`
- IV를 0으로 초기화하고 암호화/복호화 수행

전환 후:
- KEM 컨텍스트 초기화
- 세션 키 생성 및 검증용 DEM 컨텍스트 준비
- nonce, IV, 인증 태그를 포함한 상태 초기화

설계 고려:
- DES는 단순 CBC 구조였던 만큼, 현대 보안 표준은 nonce 기반 암호로 전환하는 것이 적절하다.
- 암호화/복호화 컨텍스트와 식별값을 함께 관리해야 한다.

### (4) 연산 실행

현재:
- 타임스탬프를 암호문으로 변환해 전송
- 서버가 복호화 후 `abs(myTime.tv_sec - timeStamp.tv_sec) < TIMESKEW` 규칙으로 인증을 판정

전환 후:
- 클라이언트는 세션 키를 사용해 메시지에 대한 인증 태그 생성
- 서버는 동일 키로 검증
- 허용 시간 값과 메시지 신뢰성을 함께 고려한 인증 로직으로 재구성

권장 전환:
- 단순 시간 차이 비교는 “정상 타이밍” 검증만 수행하므로 보안성이 낮다.
- 메시지의 무결성, 키 ID, 인증 결과를 함께 검증해야 한다.

### (5) 결과 처리

현재:
- 서버가 `yes` 또는 `no`를 클라이언트로 전송

전환 후:
- 인증 성공/실패에 대한 구조화된 결과와 로그를 제공
- 실수/오류/오래된 키/타임아웃을 구분해서 처리
- 전송된 메시지에 알고리즘 식별과 서명/태그 정보 포함

권장 사항:
- 인증 실패 사유를 세분화해서 운영자가 원인 파악 가능하게 해야 한다.
- 메타데이터와 보안 로그를 함께 기록한다.

## 5. 적용 우선순위

1. DES 기반 키 공유 구조를 KEM 기반으로 교체
2. 타임스탬프 단순 비교 인증 로직을 안전 인증 구조로 변경
3. 실제 데이터 보호 모드인 CBC → AES-GCM 기반 구조로 전환
4. 키 저장 방식과 실패 처리 정책 개선

## 6. 요약

이 장은 소켓 기반의 간단한 보안 프로토콜 예제이지만, 양자내성 전환을 가장 실질적으로 적용해야 하는 장 중 하나다. 이유는 보안의 근간이 “공유 secret key + 단순 시간 비교” 구조이기 때문이다. PQC 전환에서는 이 구조 자체를 KEM 기반 세션키 교환 + 검증 가능한 메시지 인증으로 바꾸는 것이 핵심이다.
